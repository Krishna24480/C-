CHAPTER 01

What is OOPs?

OOPs stands for Object-Oriented Programming System. It is a programming paradigm in which programs are organized around objects that combine data and functions.

C++ supports procedural programming as well as object-oriented programming. OOP is especially useful when developing large applications that need reusable, organized and maintainable code.

Real-world example: A car

A car has data such as its brand, color and speed.

It also has actions such as starting, braking and accelerating.

In an object-oriented program, these properties and actions can be represented together in a class.

Procedural programming vs OOP

Procedural approach Object-oriented approach
Organizes code around functions. Organizes code around classes and objects.
Data and functions are often separate. Data and related functions can be grouped.
Code reuse can use functions. Reuse can also use inheritance and composition.
Useful for many small, task-focused programs. Useful for modeling complex systems and relationships.

CHAPTER 02

Class and Object

What is a class?

A class is a user-defined type that groups data members and member functions into one unit. It acts as a blueprint for creating objects.

What is an object?

An object is an instance of a class. Each ordinary object has its own non-static data members.

Example: A class is the blueprint of a house. Individual houses built from that blueprint are objects.

#include <iostream>
#include <string>
using namespace std;

class Student {
public:
    string name;
    int age;

    void display() {
        cout << "Name: " << name << endl;
        cout << "Age: " << age << endl;
    }
};

int main() {
    Student s1;

    s1.name = "Rahul";
    s1.age = 20;

    s1.display();
    return 0;
}

Output

Name: Rahul
Age: 20

Important class concepts

  • Data members: Variables declared inside a class.
  • Member functions: Functions belonging to a class.
  • Instantiation: Creating an object of a class.
  • Dot operator (.): Accesses accessible members through an object.

CHAPTER 03

Access Specifiers

Access specifiers control which parts of a program can access class members.

Specifier Inside class Outside class Derived class
public Yes Yes, through accessible objects or other valid access Yes, subject to inheritance rules
private Yes No direct access No direct access to the base's private members
protected Yes No direct access Yes, subject to inheritance rules 
class BankAccount {
private:
    double balance = 0;

public:
    void deposit(double amount) {
        if (amount > 0) {
            balance += amount;
        }
    }

    double getBalance() const {
        return balance;
    }
};

int main() {
    BankAccount account;
    account.deposit(500);
    cout << account.getBalance();

    // account.balance = 1000; // Error: private member
}

Remember: Class members are private by default. Members of a struct are public by default.

CHAPTER 04

Encapsulation

Encapsulation means combining data and the functions that operate on it into a class, while controlling how that data is accessed.

Making data private and providing validated public operations is a common way to implement encapsulation. 

class Employee {
private:
    double salary;

public:
    Employee() : salary(0) {}

    void setSalary(double amount) {
        if (amount >= 0) {
            salary = amount;
        }
    }

    double getSalary() const {
        return salary;
    }
};

Why use encapsulation?

  • Prevents uncontrolled direct modification of private data.
  • Allows validation before changing an object's state.
  • Makes code easier to maintain.
  • Hides implementation details behind a public interface.

CHAPTER 05

Abstraction

Abstraction means exposing the essential operations of a system while hiding unnecessary implementation details.

Real-world example: ATM

You select Withdraw and enter an amount. You do not need to understand the internal banking network or cash-dispenser mechanism to use the feature.

In C++, abstraction can be achieved with classes, public interfaces and abstract classes.

#include <iostream>
using namespace std;

class Shape {
public:
    virtual double area() const = 0;

    virtual ~Shape() = default;
};

class Rectangle : public Shape {
private:
    double width;
    double height;

public:
    Rectangle(double w, double h)
        : width(w), height(h) {}

    double area() const override {
        return width * height;
    }
};

int main() {
    Rectangle r(5, 4);
    cout << r.area();
}

The abstract class defines what a shape must provide. The Rectangle class supplies the implementation.

CHAPTER 06

Inheritance

Inheritance allows a derived class to acquire accessible members and behavior from a base class. It supports reuse and the modeling of "is-a" relationships. 

#include <iostream>
using namespace std;

class Animal {
public:
    void eat() {
        cout << "Animal is eating\n";
    }
};

class Dog : public Animal {
public:
    void bark() {
        cout << "Dog is barking\n";
    }
};

int main() {
    Dog d;
    d.eat();
    d.bark();
}

Types of inheritance

1. Single inheritance

One derived class inherits from one base class.

class A {};
class B : public A {};

2. Multiple inheritance

One derived class inherits from multiple base classes.

class A {};
class B {};
class C : public A, public B {};

3. Multilevel inheritance

A class derives from a class that is already derived.

class A {};
class B : public A {};
class C : public B {};

4. Hierarchical inheritance

Multiple derived classes inherit from the same base class.

class A {};
class B : public A {};
class C : public A {};

5. Hybrid inheritance

A combination of two or more inheritance structures.

class A {};
class B : public A {};
class C : public A {};
class D : public B, public C {};

In this diamond structure, D may contain two A subobjects. Virtual inheritance can share one common A base subobject.

Public, protected and private inheritance

The inheritance mode changes the accessibility of inherited public and protected members. A base class's private members remain inaccessible directly to derived classes. 

class Base {
public:
    int x = 10;

protected:
    int y = 20;

private:
    int z = 30;
};

class Derived : public Base {
public:
    void show() {
        cout << x << " " << y;
        // z cannot be accessed directly here
    }
};

CHAPTER 07

Polymorphism

Polymorphism means "many forms". It lets the same function name or interface behave differently depending on the arguments or the actual object involved.

1. Compile-time polymorphism

The compiler resolves which overloaded function or operator to use based on the types and expressions involved.

Function overloading

#include <iostream>
using namespace std;

class Calculator {
public:
    int add(int a, int b) {
        return a + b;
    }

    double add(double a, double b) {
        return a + b;
    }

    int add(int a, int b, int c) {
        return a + b + c;
    }
};

int main() {
    Calculator c;
    cout << c.add(2, 3) << endl;
    cout << c.add(2.5, 3.5) << endl;
    cout << c.add(1, 2, 3);
}

Operator overloading

Operator overloading defines how an existing C++ operator works for a user-defined type. 

#include <iostream>
using namespace std;

class Number {
public:
    int value;

    Number(int v) : value(v) {}

    Number operator+(const Number& other) const {
        return Number(value + other.value);
    }
};

int main() {
    Number a(10), b(20);
    Number c = a + b;

    cout << c.value;
}

2. Runtime polymorphism

Runtime polymorphism commonly uses virtual functions and base pointers or references. The overridden function is selected according to the object's dynamic type. 

#include <iostream>
using namespace std;

class Animal {
public:
    virtual void sound() const {
        cout << "Animal sound\n";
    }

    virtual ~Animal() = default;
};

class Dog : public Animal {
public:
    void sound() const override {
        cout << "Dog barks\n";
    }
};

class Cat : public Animal {
public:
    void sound() const override {
        cout << "Cat meows\n";
    }
};

int main() {
    Dog dog;
    Cat cat;

    Animal& a1 = dog;
    Animal& a2 = cat;

    a1.sound();
    a2.sound();
}

Function overloading vs overriding

Overloading Overriding
Usually same name, different parameter lists. Derived class supplies a new implementation of a virtual base function.
Resolved at compile time. Supports runtime dispatch when called virtually.
Does not require inheritance. Requires an inherited virtual function for virtual overriding.

CHAPTER 08

Constructors

A constructor is a special member function that initializes an object when it is created. It has the same name as the class and has no return type.

Default constructor

class Student {
public:
    int age;

    Student() : age(0) {}
};

Parameterized constructor

class Student {
public:
    string name;
    int age;

    Student(string n, int a) : name(n), age(a) {}
};

// Student s("Rahul", 20);

Copy constructor

Initializes an object from another object of the same type.

class Box {
public:
    int value;

    Box(int v) : value(v) {}

    Box(const Box& other) : value(other.value) {}
};

// Box a(10);
// Box b(a);

Move constructor

A move constructor can transfer resources from an object that is about to be discarded, instead of copying those resources. 

#include <utility>

class Box {
public:
    unique_ptr<int> value;

    Box(int v) : value(make_unique<int>(v)) {}

    Box(Box&& other) noexcept
        : value(move(other.value)) {}
};

This example requires #include <memory> and #include <utility>, plus using namespace std; or qualified standard-library names.

Constructor overloading

A class can define multiple constructors with different parameter lists to support different initialization options.

Important constructor rules

  • Constructors do not have return types.
  • Constructors can be overloaded.
  • Constructors are not inherited in the same way as ordinary member functions, though derived classes can inherit constructor declarations with using.
  • Use member initializer lists to initialize members, especially const members and references.
  • Declaring some constructors can prevent the compiler from generating a default constructor automatically.

CHAPTER 09

Destructors

A destructor runs when an object's lifetime ends. It is commonly used to release resources owned by that object. 

#include <iostream>
using namespace std;

class Demo {
public:
    Demo() {
        cout << "Constructor called\n";
    }

    ~Demo() {
        cout << "Destructor called\n";
    }
};

int main() {
    Demo d;
}

Output

Constructor called
Destructor called
  • A class has one destructor, not an overloaded set.
  • A destructor has no return type or parameters.
  • Local automatic objects are normally destroyed when they leave scope.
  • A polymorphic base class generally needs a public virtual destructor if objects may be deleted through base pointers.
  • Prefer standard resource-managing types such as string, vector and unique_ptr instead of manual memory management.

CHAPTER 10

The this Pointer

In a non-static member function, this points to the object on which the function is being called. 

class Student {
public:
    int age;

    Student(int age) {
        this->age = age;
    }

    Student& setAge(int age) {
        this->age = age;
        return *this;
    }
};

Here, this->age refers to the object's member, while age refers to the constructor or function parameter.

CHAPTER 11

Static Data Members and Functions

A static data member belongs to the class rather than to each individual object. A static member function can be called using the class name and cannot use this. 

#include <iostream>
using namespace std;

class Student {
public:
    inline static int count = 0;

    Student() {
        count++;
    }

    static void showCount() {
        cout << count;
    }
};

int main() {
    Student a, b, c;
    Student::showCount();
}

Output: 3. The example uses an inline static data member, supported in C++17 and later.

CHAPTER 12

Friend Function and Friend Class

A friend function or class can access the private and protected members of the class that declares it as a friend. 

#include <iostream>
using namespace std;

class Box {
private:
    int value = 100;

    friend void show(const Box& b);

public:
    Box() = default;
};

void show(const Box& b) {
    cout << b.value;
}

int main() {
    Box b;
    show(b);
}

Friend access is granted explicitly by the class. Friendship is not automatically mutual or inherited.

CHAPTER 13

Virtual Functions and Abstract Classes

Virtual function

A virtual function enables dynamic dispatch when called through an appropriate base pointer or reference.

Pure virtual function

A pure virtual function is declared with = 0. It makes the class abstract when the class has an unimplemented pure virtual requirement. 

class Payment {
public:
    virtual void pay(double amount) = 0;
    virtual ~Payment() = default;
};

class UpiPayment : public Payment {
public:
    void pay(double amount) override {
        cout << "Paid using UPI: " << amount;
    }
};

You cannot create an object of the abstract class Payment, but you can use a Payment pointer or reference to refer to a concrete derived object.

CHAPTER 14

Object Relationships and Special Concepts

Association

A general relationship between two objects. For example, a teacher teaches a student.

Aggregation

A whole-part relationship in which the parts can have an independent lifetime. For example, a department can refer to teachers who exist independently of it.

Composition

A strong whole-part relationship in which a containing object owns its components and manages their lifetimes. For example, a car object might own an engine object.

Early binding and late binding

Early binding resolves a call before runtime. Late binding resolves the appropriate virtual function at runtime based on dynamic type.

Shallow copy and deep copy

A shallow copy copies member values as they are represented. If a member is a raw pointer, this copies the pointer address, not the resource it points to. A deep copy duplicates the owned resource where appropriate.

Modern C++ often avoids manual deep-copy logic by using resource-managing types and the Rule of Zero.

CHAPTER 15

Dynamic Objects and Memory Management

Objects can be created dynamically when their lifetime or allocation needs to be controlled. In modern C++, smart pointers are preferred to owning raw pointers. 

#include <iostream>
#include <memory>
using namespace std;

class Student {
public:
    Student() {
        cout << "Student created\n";
    }
};

int main() {
    auto student = make_unique<Student>();

    // The Student is destroyed automatically
    // when student leaves scope.
}

unique_ptr provides exclusive ownership. shared_ptr provides shared ownership, while weak_ptr observes an object managed by shared_ptr without extending its lifetime.

Avoid pairing raw new and delete unnecessarily. Prefer RAII and standard-library containers.

CHAPTER 16

Const Member Functions and Objects

A const member function promises not to modify the object's non-mutable data members through the implicit object parameter. 

class Circle {
private:
    double radius;

public:
    Circle(double r) : radius(r) {}

    double getRadius() const {
        return radius;
    }

    double area() const {
        return 3.14159 * radius * radius;
    }
};

A const object can call const member functions, but generally cannot call non-const member functions.

CHAPTER 17

Namespaces and Scope Resolution

Namespaces organize names and help prevent naming conflicts. The scope resolution operator :: accesses a name within a scope. 

#include <iostream>

namespace First {
    int value = 10;
}

namespace Second {
    int value = 20;
}

int main() {
    std::cout << First::value << '\n';
    std::cout << Second::value;
}

Prefer explicit namespace qualification in larger projects instead of placing using namespace std; in public headers.

CHAPTER 18

Rule of Three, Five and Zero

Rule of Three

If a class needs a custom destructor, copy constructor or copy assignment operator because it manages a resource, it may need all three.

Rule of Five

Modern C++ adds the move constructor and move assignment operator to the three copy/destruction operations.

Rule of Zero

Prefer member types that manage their own resources so the class does not need custom copy, move or destruction functions. 

#include <string>
#include <vector>

class Team {
private:
    std::string name;
    std::vector<std::string> members;

public:
    Team(std::string n, std::vector<std::string> m)
        : name(std::move(n)), members(std::move(m)) {}
};

This class can use compiler-generated copy, move and destruction behavior because its standard-library members manage their resources.
